Git, gh e chave SSH no GitHub

Ligar o seu computador à sua conta do GitHub com chave SSH, criar o repositório (público ou privado) e publicar a página.

0%0 de 0
6passos
~20 minmão na massa
2/4trilha
3idiomas · languages

1Diga ao Git quem é você

git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"
git config --global --list

Você vê: user.name=Seu Nome e user.email=seu@email.com na lista.

O que é

Use o mesmo e-mail da sua conta do GitHub. É feito uma vez por computador.

Por que aprender

Cada versão salva leva o seu nome. O GitHub usa o e-mail para ligar as versões à sua conta.

Conceitos-chave

git config: ajusta o Git. --global: vale para todos os projetos deste computador. Commit: uma versão salva do projeto, com autor e mensagem.

Deu erro?

Errou o nome ou o e-mail? Rode o mesmo comando de novo com o valor certo: ele substitui o anterior.

2Crie a sua chave SSH

ssh-keygen -t ed25519 -C "seu@email.com"
explorer %USERPROFILE%\.ssh

Você vê: Na pasta .ssh: id_ed25519 (chave privada) e id_ed25519.pub (chave pública).

O que é

Aperte Enter nas 3 perguntas para aceitar o local padrão e seguir sem senha extra. Depois o explorer abre a pasta onde as chaves ficaram.

Por que aprender

A chave SSH é a sua identidade sem senha: o GitHub e a VPS reconhecem o seu computador por ela.

Conceitos-chave

SSH: forma segura de conectar dois computadores. Chave privada: fica só na sua máquina, nunca se envia. Chave pública (.pub): é a que você entrega ao GitHub e à VPS.

Deu erro?

Perguntou se quer sobrescrever (Overwrite)? Você já tem uma chave. Responda n e use a que existe.

3Conecte o gh à sua conta e envie a chave

gh auth login
ssh -T git@github.com

Você vê: Hi SEU-USUARIO! You've successfully authenticated.

O que é

Responda: GitHub.com → SSH → escolha id_ed25519.pub → Login with a web browser. Copie o código, cole no navegador e autorize. Depois teste a chave; na primeira vez responda yes.

Por que aprender

Um comando faz o login e manda a sua chave pública para a conta, sem abrir configurações no site.

Conceitos-chave

gh auth login: entra na sua conta do GitHub pelo terminal. Protocolo SSH: o Git passa a usar a sua chave em vez de senha. ssh -T: testa a conexão sem abrir nada.

Deu erro?

O gh mostrou a chave com outro nome ou ofereceu gerar uma nova? Escolha a que termina em .pub na sua pasta .ssh. “Permission denied (publickey)”: a chave não foi enviada; rode gh auth login de novo e escolha SSH.

4Crie o repositório e envie o projeto

cd %USERPROFILE%\projetos\meu-site
git init
git add .
git commit -m "primeira versão"
git branch -M main
gh repo create meu-site --public --source=. --push

Você vê: O endereço https://github.com/SEU-USUARIO/meu-site com os seus arquivos.

O que é

git init liga o Git na pasta, add e commit salvam a primeira versão, e o gh cria o repositório e envia tudo. Para privado, troque --public por --private.

Por que aprender

Público: qualquer pessoa vê (necessário para Pages grátis). Privado: só você e quem você convidar. Você decide por projeto.

Conceitos-chave

Repositório: a pasta do projeto com todo o histórico, guardada no GitHub. Branch main: a linha principal de versões. Push: enviar as versões para o GitHub.

Deu erro?

“nothing to commit”? A pasta está vazia: volte ao passo 7 da parte 1. “Name already exists”? Você já tem um repositório com esse nome: escolha outro.

5Publique a página no GitHub Pages

gh api repos/{owner}/{repo}/pages -X POST -f "source[branch]=main" -f "source[path]=/"

Você vê: Em alguns minutos a página abre em https://SEU-USUARIO.github.io/meu-site/

O que é

Este comando liga o GitHub Pages no repositório da pasta atual. Também dá pelo site: Settings → Pages → branch main → Save.

Por que aprender

Você sai com um link público da página que o agente criou, sem pagar hospedagem.

Conceitos-chave

GitHub Pages: hospedagem grátis de páginas a partir de um repositório. {owner} e {repo}: o gh troca sozinho pelo seu usuário e pelo nome do repositório.

Deu erro?

Página 404 logo depois? Espere de 2 a 10 minutos e recarregue. Erro sobre plano? Pages grátis só funciona em repositório público.

6A rotina de todo dia

git status
git add .
git commit -m "o que mudou"
git push

Você vê: git status lista o que mudou; depois do push a mudança aparece no GitHub e, em minutos, na página.

O que é

Mudou algo? Veja o que mudou, salve uma versão com uma frase e envie. Ou peça ao agente: salve e envie para o GitHub.

Por que aprender

Cada commit é um ponto de volta. Se algo quebrar, dá para recuperar a versão anterior.

Conceitos-chave

git status: mostra o que mudou desde a última versão. Mensagem do commit: uma frase que diz o que mudou, para você se achar depois.

Deu erro?

Push recusado com “fetch first”? Alguém (ou você noutra máquina) mudou o repositório. Rode git pull e depois git push.
